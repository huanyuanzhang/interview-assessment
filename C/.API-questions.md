Before accessing invoice data, I will verify the Xero API connection in these ways:
1.First call the simplest health check or /connections endpoint to confirm we get a 200 OK response.
2.Verify the OAuth2 access token is valid, not expired, and has correct scope permissions.
3.Check network connectivity, firewall rules, and correct Xero tenant ID configuration.
4.Ensure API credentials (client ID, client secret, redirect URI) are properly set up.

C2:
1.Check the request URL, HTTP method, headers and query parameters for any mistakes.
2.Check if the Xero organisation has no invoice data or has restricted API access.
3.Look at the error response code and message to identify permission, rate-limit or data issues

C5:
When the API returns 429 Too Many Requests, it means we have hit the Xero rate limit.
The backend should:
1.Implement exponential backoff retry (retry after waiting longer each time).
2.Respect the Retry-After header in the response.
3.Add a request queue to throttle API calls.
4.Avoid immediate, repeated retries to prevent further blocking.
